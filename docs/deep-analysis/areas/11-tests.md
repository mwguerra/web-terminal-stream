# 11 — Test suite structure, coverage, CI

**Area key:** `tests`

## Summary

The test suite is unusually mature for a pre-1.0 library: ~386 unit tests across 31 files (tests/Unit) plus a real 3-test Integration suite that spawns the actual ReactPHP server and round-trips through token auth + cache pull + a live SSH PTY (tests/Integration/WebSocket/FullStackServerTest.php), a Linux-native PTY-resize test, and 9 Playwright e2e specs. CI (.github/workflows/tests.yml) runs three jobs: a unit matrix (PHP 8.3/8.4 x Laravel 12/13), a Docker-sshd integration job with WTS_REQUIRE_DOCKER=1 (so absence hard-fails instead of silently skipping), and a Playwright e2e job that scaffolds the gitignored host app. Coverage is deep on the public API surface (Data objects, Enums, Schemas components, the Livewire trio, Themes, TerminalLogger, plugin config, OriginValidator, PtySessionRegistry, TerminalPtyBridge against a real /bin/sh) and the server error-recovery seam is tested via reflection (ReactPhpWebSocketServerLoopSafetyTest). The gaps are the operational periphery, not the core data path: all four Artisan commands, InteractiveSsh, TerminalLogListener, and the entire Filament Resource UI have zero unit coverage. Two known-issue defects are real and confirmed: composer analyse is broken (points at an uninstalled binary), and the Pest dataset-scan OOM workaround is incomplete — it protects composer scripts but not the two dev commands the project's own CLAUDE.md documents, which hang outright on any machine that has scaffolded the e2e host app.

## What exists and works

- ~386 real unit tests across 31 files under tests/Unit (verified: 32 in WebTerminalStreamTest, 31 LayoutTree, 29 Script, 23 each TerminalLogger/TerminalGrid, etc.)
- Real full-stack integration test: FullStackServerTest.php spawns terminal-stream:serve as a separate process sharing APP_KEY+file cache, and asserts a genuine echo round-trip through token auth -> Cache::pull -> SSH PTY (lines 117-145), plus Origin rejection without burning the token (147-159), garbage-token close (161-166), and single-use token reuse rejection (168-184) — strong, non-tautological assertions
- TerminalPtyBridge unit tests spawn a real /bin/sh PTY and assert actual echoed output, PID registration in the registry, and unregister-on-terminate (tests/Unit/WebSocket/TerminalPtyBridgeTest.php:29-71)
- Server loop-safety tested via reflection-injected throwing bridges: asserts the offending connection is closed AND evicted from the registry while sibling sessions survive (ReactPhpWebSocketServerLoopSafetyTest.php:190-213) — real behavioral assertions, not just not->toThrow
- Linux-native PTY resize test asserts stty actually reports the new 40x120 dimensions after resize()+SIGWINCH (LinuxResizeTest.php:33-42), grouped linux-pty and OS-guarded
- Integration skip-vs-fail contract is correct: requireSshTarget() (Pest.php:83-100) skips gracefully on a dev machine but hard-fails under CI/WTS_REQUIRE_DOCKER, and the CI integration job sets WTS_REQUIRE_DOCKER=1 so a silently-all-skipped suite cannot pass green
- The divider-drag e2e test (split-interactions.spec.js:42-71) was hardened against the exact false-positive the audit warned about — it now asserts the pane width delta approx equals the drag distance (>0.6x, <1.4x of 150px), not merely width != before
- 9 Playwright e2e specs (single-terminal, split-panes, split-interactions, pane-controls, dashboard, custom-keymap, manual-connect, themed, security) wired into a dedicated CI job with artifact upload on failure
- Filament plugin configuration is thoroughly unit-tested (WebTerminalStreamPluginTest.php, 21 tests: registration, withoutTerminalPage/Logs, components() whitelist, navigation defaults)
- phpunit.xml enforces failOnRisky + failOnWarning + beStrictAboutCoverageMetadata + beStrictAboutOutputDuringTests, and the PTY tests keep output internal (read()) so they don't trip the strict-output guard

## Flaws (implemented but wrong/risky)

Each critical/high flaw was handed to an independent skeptic instructed to refute it.

### Pest OOM/hang workaround is incomplete — the project's own documented dev commands hang
- **Severity:** high — **Verdict:** ✅ confirmed
- **Files:** composer.json, CLAUDE.md, .github/workflows/tests.yml, .gitignore
- **Detail:** Pest's BootFiles::bootDatasets() recursively walks the whole tests/ tree, including the gitignored 16,875-file tests/e2e-app, on every invocation (confirmed via stack trace: bootDatasets -> php-file-iterator/Facade.php). The mitigation is memory_limit=-1, but it lives ONLY in the composer scripts (composer.json: test/test:parallel/test:coverage/test:integration). The two commands CLAUDE.md tells contributors to run — `vendor/bin/pest tests/Unit/Livewire/StreamTerminalTest.php` and `vendor/bin/pest --filter=...` (CLAUDE.md:30-31) — carry no override and reproducibly die at bootDatasets on any machine that has scaffolded the e2e app (I captured `PHP Fatal error: Maximum execution time exceeded in php-file-iterator/src/Facade.php ... bootDatasets`). Worse, even WITH memory_limit=-1 the boot spends 90s+ scanning 16k files before running a single test. The correct fix (stop Pest from treating tests/e2e-app as a dataset root — e.g. relocate the host app outside tests/, or configure Pest's test dirs) is absent, so the workaround is fragile: the CI integration job runs raw `vendor/bin/pest --testsuite=Integration` (tests.yml:52) with no override and survives only because e2e-app happens not to exist in that job.
- **Evidence:** Confirmed fatal: running `php -d memory_limit=128M vendor/bin/pest tests/Unit/Livewire/StreamTerminalTest.php` (the CLAUDE.md-documented form) dies with `Maximum execution time ... exceeded in vendor/phpunit/php-file-iterator/src/Facade.php ... #2 Pest\Bootstrappers\BootFiles->bootDatasets`. .gitignore:14 confirms /tests/e2e-app/; find counts 16,875 files there. Overrides exist only in composer.js
- **Verifier:** REAL and reproduced. Pest's BootFiles::bootDatasets (vendor/pestphp/pest/src/Bootstrappers/BootFiles.php:62,83) scans the entire tests/ tree via getFilesAsArray($testsPath,'.php') regardless of the CLI file/testsuite argument — $testsPath is rootPath+testDirectory(), not the passed path. .gitignore:

### composer analyse is broken — points at an uninstalled binary with no config
- **Severity:** medium — **Verdict:** ⚪ unverified
- **Files:** composer.json, CLAUDE.md
- **Detail:** composer.json defines "analyse": "vendor/bin/phpstan analyse", but phpstan/phpstan is not in require-dev and is not installed (vendor/bin/phpstan does not exist), and there is no phpstan.neon anywhere in the repo. Running `composer analyse` exits 127 (`sh: vendor/bin/phpstan: No such file or directory ... returned with error code 127`). CLAUDE.md advertises `composer analyse` as the static-analysis command, so a contributor following the docs hits an immediate failure. It is also absent from CI, so no static analysis actually runs anywhere. Either add phpstan/phpstan + a phpstan.neon (and a CI step) or remove the misleading script.
- **Evidence:** `composer analyse` -> `sh: vendor/bin/phpstan: No such file or directory` exit 127; `grep -i phpstan composer.json` shows only the analyse script line, no require-dev entry; no phpstan.neon* exists; vendor/phpstan contains only phpdoc-parser (a transitive dep), not phpstan itself.

### Tautological/placeholder assertions that pass regardless of the feature
- **Severity:** low — **Verdict:** ⚪ unverified
- **Files:** tests/Unit/WebSocket/TerminalPtyBridgeTest.php, tests/Unit/ExampleTest.php, tests/Integration/LocalPty/LinuxResizeTest.php
- **Detail:** Two tests assert nothing about the code under test. (1) tests/Unit/ExampleTest.php:5 `it('can run a basic test', fn() => expect(true)->toBeTrue())` is a leftover scaffold placeholder. (2) tests/Unit/WebSocket/TerminalPtyBridgeTest.php:80-81 — the resize unit test calls $bridge->resize(120,40) then asserts `expect(true)->toBeTrue()`; it would pass even if TerminalPtyBridge::resize() were an empty method. The real resize behavior is only verified by LinuxResizeTest, which is Linux-gated and therefore skipped on the macOS dev machine — so on a contributor's Mac, resize() has no effective assertion at all. Replace the resize placeholder with a behavioral check (or move it to the Linux integration test and drop the fake unit assertion).
- **Evidence:** tests/Unit/WebSocket/TerminalPtyBridgeTest.php:80-81 `$bridge->resize(120, 40); expect(true)->toBeTrue();`; tests/Unit/ExampleTest.php:5 `expect(true)->toBeTrue();`; LinuxResizeTest.php:16-18 skips on non-Linux, so the only genuine resize assertion (stty reports '40 120') does not run on macOS.
