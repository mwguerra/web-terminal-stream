# Terminal Lifecycle Flow Map

Mapped all 8 end-to-end terminal lifecycle flows. The happy paths are coherent and the client/server contract (token issuance -> single-use Cache::pull -> PTY bridge -> 10ms tick streaming -> resize -> teardown) is largely sound and matches the documented architecture. The dominant problem is that ReactPhpWebSocketServer::handleHandshake runs bridge startup (and a null-int cast) with NO exception guard inside the ReactPHP 'data' callback: an SSH auth failure, a guest/null userId, or a proc_open failure throws an uncaught exception that propagates out of Loop::run() and kills the entire long-running server — dropping every other user's live session. SSH connect is also performed synchronously inside the handshake, freezing all sessions for up to the SSH timeout. Secondary issues: dead shells (user types `exit`) are never closed server-side so the client stays falsely "connected" and bridges leak; disconnect logging/events are unreliable on SPA navigation and pane close; and the Livewire getWebSocketUrl() hardcodes ws:// which is mixed-content-blocked on HTTPS pages unless websocket_url is manually set (the controller path gets this right, the primary path does not).

| Flow | Status | Trigger | Notes |
|---|:--:|---|---|
| 1. Connect LOCAL terminal | ⚠️ flawed | Alpine init() IntersectionObserver (auto/always) or startSession() (manual) -> initStream() boots ghostty -> connect() -> $wire.getWebSocketUrl() -> ws.onopen -> $wire.connect() | Happy path works on Linux. Flawed: (a) proc_open failure throws RuntimeException uncaught in the handshake data callback -> whole server crashes (see flaw #1). (b) Platform-coupled to Linux: 'setsid' binary and /proc/<pid>/fd/0 do not exist on macOS/BSD (dev machine is darwin) — the shell dies immediately / resize is a no-op with no error surfaced. (c) TerminalConnectedEvent is fired on ws.onopen from the client, before/independent of the server confirming the PTY actually started, so a connect can be logged for a session the server never established. |
| 2. Connect SSH terminal | ⚠️ flawed | same as local, config.type=ssh -> TerminalPtyBridge::startSsh -> InteractiveSsh::login + write('', CHANNEL_SHELL) | Two serious flaws: (a) On wrong password/key InteractiveSsh::login returns false -> startSsh throws RuntimeException, uncaught in the handshake data callback -> ENTIRE server process crashes (flaw #1). Wrong SSH password is a common path. (b) login() and the whole SSH handshake run SYNCHRONOUSLY inside handleHandshake on the shared ReactPHP event loop — a slow or unreachable SSH host blocks tick() and every other active session for up to the configured timeout (5-10s+) (flaw #2). |
| 3. Disconnect + teardown | 🟡 partial | client 1000 close (disconnect button), beforeunload/pagehide/livewire:navigating (destroy()), server-side shell exit, or network drop | PTY/registry teardown is solid and idempotent (handleClose runs twice on OP_CLOSE but is guarded). Gaps: (a) destroy() on livewire:navigating/pagehide closes the socket but never calls $wire.disconnect(), and the component is being torn down, so TerminalDisconnectedEvent + the disconnect log row are silently skipped on the most common exit path — navigating away (gap in flow #8). (b) When the shell itself exits (`exit` command / crash), tick() sees isRunning()===false and just `continue`s forever — it never closes the socket, so the client stays visually 'connected' and the dead bridge lingers in memory until the client leaves or max_session_lifetime (flaw #3). |
| 4. Token issuance + single-use replay defense + expiry | ✅ complete | $wire.getWebSocketUrl() (Livewire) or POST terminal-stream/ws-token (controller) | Replay defense is correct: single-use is enforced by Cache::pull (a replayed token finds configData===null and is closed). Expiry checked (exp < time()). Origin allow-list is correctly enforced BEFORE the token is consumed so a rejected page can't burn a stolen token. Minor: a connect attempt that never opens the socket (server down) leaves the cached config until the 300s TTL — harmless, self-expiring. One real defect feeding flaw #1: a guest/unauthenticated issuer sets payload userId=auth()->id()=null, which under strict_types crashes the server when cast to the int userId param. |
| 5. Resize propagation | ⚠️ flawed | FitAddon.observeResize() + terminal.onResize -> ws.send({type:resize,cols,rows}); also initial resize on ws.onopen | SSH resize path is correct and thoughtfully implemented (window-change on the live channel rather than setWindowSize which only affects pty-req). Local resize is Linux-only: it depends on /proc/<pid>/fd/0 and the stty binary; on macOS/BSD readlink fails, stty is skipped, and only SIGWINCH is sent so apps re-query an unchanged kernel TTY size — resize is effectively a no-op off Linux. cols/rows validated only for <=0. |
| 6. Workspace splitPane / closePane | ✅ complete | tmux prefix keymap (onKeydown) or per-pane close button -> $wire.splitPane/closePane/spawnPane/updateRatios | Security model is sound: client only sends paneId/orientation/ratios; new pane config is a server-side clone of the source or the Locked template, never client input; every mutation re-checks the useStreamTerminal gate; unknown split ids ignored. Closing a pane removes its keyed div -> Livewire morph destroys the nested StreamTerminal -> Alpine destroy() closes its WebSocket -> server tears down that PTY. Correct isolation. (Shares the disconnect-logging gap from flow #3 for the closed pane.) |
| 7. Dashboard toggle open/close | ✅ complete | source button -> Alpine toggle(sourceId) -> $wire.toggle(sourceId) | Correct. Client sends only a source id; config comes from the #[Locked] sources roster; open re-checks the gate and the maxOpen cap (clamped 1..4). Closing removes the keyed pane -> nested StreamTerminal destroyed -> WS + PTY torn down. Same disconnect-logging asymmetry as flow #3 applies. |
| 8. Connection lifecycle logging | ⚠️ flawed | $wire.connect() (ws.onopen) writes connect row; $wire.disconnect() writes disconnect row | Flaws: (a) disconnect rows are frequently never written — destroy() on navigation/pane-close closes the socket without calling $wire.disconnect(), so many sessions get a CONNECTED row with no DISCONNECTED row; getSessionSummary then computes duration to now() indefinitely (flaw #4). (b) $wire.connect() has NO gate/authz check (unlike getWebSocketUrl) — any user on the page can call it directly to spam bogus TerminalConnectedEvents / connect log rows without ever opening a socket (flaw #5, low). (c) Logging depends entirely on a client Livewire round-trip; the server (which authoritatively knows when a PTY starts/ends) writes no logs, so accuracy is inherently best-effort. |
