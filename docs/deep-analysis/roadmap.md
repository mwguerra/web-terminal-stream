# Prioritized Roadmap

Production-readiness assessment and prioritized fixes from the deep-analysis audit (12 areas, adversarially verified). Refuted findings are excluded. Severity buckets: **P0** = blocks any production tag (security/availability/data correctness); **P1** = broken common paths / major operational risk; **P2** = polish, parity, hardening; **Quick wins** = <1h, disproportionate value.

## Verdict

NOT production-ready. This library exposes raw interactive shell/SSH access, and the audit surfaced a critical authorization hole plus multiple availability/resource-leak defects that make a public tag irresponsible today. The single most serious issue is that the REST token endpoint (TerminalWebSocketController::generateToken) skips the useStreamTerminal Gate AND trusts a fully client-supplied connectionConfig, so ANY authenticated user can mint a valid token for an arbitrary local shell on the app host or an SSH pivot to any host/credentials — this defeats every invariant the (otherwise sound) Livewire path enforces and is effectively authenticated RCE + SSRF. Availability is equally fragile: a single wrong SSH password or a proc_open failure throws an uncaught exception out of the ReactPHP data callback and kills the whole long-running server for every other live session (trivial DoS), there is no cap on concurrent PTYs per user or globally (shell-fork DoS), dead shells are never reaped (zombie child + FD + memory leak), and there is no backpressure, handshake-size limit, or idle timeout. The server also hard-depends on ext-posix/ext-pcntl/Unix proc_open PTYs that are neither declared in composer.json nor preflight-checked, so it installs cleanly and then fatals at runtime on unsupported hosts. Multi-tenancy is broken two ways (silent insert failures with default config; zero tenant scoping in the Filament resource = cross-tenant audit exposure). The pure layout/keymap logic, the Livewire security model, and the fluent-config layer are genuinely well-built and heavily tested — the problems are concentrated in the WS server, the REST token path, cross-process/TLS assumptions, and the operational periphery (commands, packaging, multi-tenant logging). Keep it pre-1.0. Clear the P0 authorization + availability items and add coverage for the untested command/installer surface before considering a tag.


## P0 — must fix before any tag

| Fix | Why | Effort | Area |
|---|---|:--:|---|
| REST ws-token endpoint grants any authenticated user an arbitrary shell / SSH pivot | TerminalWebSocketController::generateToken reads the entire connectionConfig from client input (line 18) with NO useStreamTerminal Gate check, then mints a valid single-use token. Route is registered unconditionally with only web+auth. Any authenticated (not privileged) user can open a local shell on the app host or SSH-pivot to any host/credentials — authenticated RCE + SSRF that bypasses every Livewire-side invariant. Confirmed. | M | security |
| Uncaught exception during handshake/bridge-start crashes the entire WS server for all sessions | handleHandshake calls bridge->start($shell) with no try/catch (ReactPhpWebSocketServer.php:169-170); startSsh throws on any wrong SSH password/key and startLocal throws on proc_open failure. The throwable propagates out of the on('data') closure and out of Loop::run(), killing the long-running process and dropping every other user's live session. Trivial one-bad-password DoS. Confirmed. | S | ws-server |
| No max-connection cap, per-user session limit, or rate-limit on token issuance | Each handshake unconditionally spawns a PTY (proc_open or SSH socket) + bridge + buffers; nothing bounds concurrent sessions per user or globally, and neither issuance path throttles token minting. An authenticated user can script token-mint + WS-connect to fork unbounded shells and exhaust host FDs/PIDs/memory (shell-fork DoS). userId is carried in the token but never enforced. Elevate to P0 given raw shell access. | M | ws-server |
| ext-posix / ext-pcntl / Unix proc_open PTY are hard runtime deps but undeclared and unchecked | The server calls posix_kill, uses the SIGWINCH (pcntl) constant, and opens PTYs via proc_open ['pty'] descriptors — all undeclared in composer.json require and absent from the serve preflight. The package installs cleanly on hosts lacking them and then fatals at runtime (notably on resize). Declare the ext-* requires and add a serve-time capability check that fails fast with a clear message. | S | config-packaging |
| Filament TerminalLogResource has zero tenant scoping — cross-tenant audit-log exposure | The package advertises multi-tenancy (tenant_column/resolver, --with-tenant migration, scopeForTenant) and writes a tenant column per row, but the resource has no getEloquentQuery() tenant filter and no ownership relationship. In a multi-tenant panel it either 500s or lists every tenant's connection audit rows (IPs, SSH hosts/usernames). Confirmed high. | M | logging-filament |
| --with-tenant migration + default config silently breaks ALL logging | The with-tenant stub declares tenant_id as NOT NULL FK (no ->nullable()), but createLog only sets the tenant column when tenant_column AND getTenantId() are both non-null (defaults are null). Every insert then violates NOT NULL and is swallowed — zero logs written, no error surfaced. A default --with-tenant install produces a silently-dead audit trail. Confirmed high. | S | logging-filament |

## P1 — should fix before real use

| Fix | Why | Effort | Area |
|---|---|:--:|---|
| Dead PTY sessions are never reaped — zombie child + open WS + stale registry entry leak | tick() does `if (!$bridge->isRunning()) continue;` (line 235-237), never closing the WS or calling terminate()/proc_close(). When a user types `exit` (common) or SSH drops, the child zombies, the FD/bridge/buffer memory and registry entry leak until the client happens to disconnect, and the browser shows a false 'connected' frozen shell. Steady leak on a long-running server. Confirmed. | M | ws-server |
| SSH connect runs synchronously inside the handshake, freezing all sessions | startSsh runs InteractiveSsh::login (TCP+DNS+KEX+auth) synchronously from handleHandshake on the single shared event loop, so tick() cannot fire and every other terminal stalls for up to the SSH timeout while one connection is established. Confirmed. | L | ws-server |
| SSH credentials stored in the cache in plaintext for the token TTL | Both issuance paths Cache::put the full connectionConfig including SSH password/private_key/passphrase in cleartext; only the token payload is encrypted. Whatever store the host uses (redis/db/memcached/file) holds harvestable credentials for signed_url_ttl. Confirmed. Encrypt the cached config blob or store only a reference to server-side-resolved credentials. | M | security |
| getWebSocketUrl hardcodes ws:// — mixed-content-blocked on HTTPS, and traffic is plaintext | The primary Livewire path (StreamTerminal.php:126) always builds ws://{host}:{port} regardless of page scheme or ssl_cert/ssl_key, so on an HTTPS Filament page the browser blocks the connection and, where it isn't blocked, all keystrokes and interactive shell/SSH output travel unencrypted. Derive wss:// from request scheme / configured TLS. (Consolidates the ws:// findings across flows/security/cross-process.) | S | cross-process |
| No SSH host allow-list — server is a usable SSH/port-scan pivot | ConnectionConfig only range-checks the port; there is no allow-list of destination hosts/ports. Combined with the client-controlled config in the REST path (P0), an authenticated user can aim SSH at any internal/external host, turning the app server into an SSRF pivot. Add a configurable host/port allow-list enforced server-side. | M | security |
| No graceful shutdown — Ctrl+C/SIGTERM orphans every live PTY | stop() only calls Loop::stop(); nothing walks active bridges to terminate() them. Because local shells are setsid-detached they survive and become reparented orphans consuming CPU/FDs. Register SIGINT/SIGTERM handlers that tear down all bridges before exit. | S | ws-server |
| No handshake size limit and no incomplete-handshake/idle timeout (unauthenticated DoS) | Pre-upgrade `$httpBuffer .= $data` (line 64) grows unbounded, so a client that never sends CRLFCRLF drives OOM, and a silent open connection is never timed out (slowloris/FD exhaustion) — all pre-auth. Cap handshake bytes and add connection/idle timeouts. | M | ws-server |
| No backpressure — unbounded WS write buffering on fast PTY vs slow client | tick() drains all available PTY output (local path loops fread(8192) with no per-tick cap) then $conn->write()s it; React buffers unbounded in-process memory when the client can't keep up, so a high-output command against a slow browser inflates server memory. Confirmed. Cap per-tick reads and pause reads on write-buffer pressure. | M | ws-server |
| Half the Filament Logs UI is permanently dead (command/output/error events never recorded) | logCommand/logOutput/logError/logBlockedCommand are called from nowhere in src/ (Stream only writes connected/disconnected), yet the copied-from-parent UI still ships Commands/Errors stat tiles (always 0), command/exit_code/execution_time columns, command/output/SSH infolist sections (always empty), and filters that never match. Confirmed. Strip the dead surface for the Stream extraction. | M | logging-filament |
| Local PTY path is Linux-only and silently dies on macOS/BSD | startLocal runs `setsid {shell} -il` and resize depends on /proc/<pid>/fd/0 + stty; macOS has no setsid binary and no /proc, so the shell dies immediately while proc_open still returns a valid resource (no exception, invisible failure) and resize no-ops. This is also the dev platform. Detect platform and provide a non-setsid/non-/proc path or fail loudly. | M | ws-server |
| Crash/PID-reuse cleanup hazards leave orphans running or SIGKILL unrelated PIDs | cleanupStale only kills registry entries older than max_session_lifetime (default 3600s), so a shell orphaned minutes before a crash keeps running after restart; and posix_kill($pid,0) before SIGKILL only proves some process holds that pid — after reboot or on a busy host the number may belong to an unrelated process. Store a start-time/owner marker and verify identity before killing. | M | ws-server |
| Disconnect events + log rows are lost on SPA navigation and pane close | stream-terminal.blade.php destroy() (beforeunload/pagehide/livewire:navigating/nested pane teardown) closes the WS but never calls $wire.disconnect(), and the component is being destroyed so no round-trip completes. Many sessions get a CONNECTED row with no DISCONNECTED row, corrupting getSessionSummary durations. Emit disconnect server-side on WS close instead of relying on the client round-trip. | M | logging-filament |
| Zero automated coverage for all four artisan commands + the 640-LOC installer | No tests reference terminal-stream:install/:make-page/:logs:cleanup/:serve; the installer (panel selection, --with-tenant migration, idempotency, scaffolding) is the highest-risk untested unit and known to have real defects (--force duplicates the timestamped migration, make-page doesn't StudlyCase/validate the class name → uncompilable file or path traversal). Add Testbench command tests and fix the guarded defects. | L | commands-install |
| Committed dist CSS is stale and nothing guards it in CI | Commit abba57d changed a Blade view but did not rebuild resources/dist/web-terminal-stream.css, which host apps load directly — the frameless fix silently doesn't ship. The e2e workflow never runs npm run build:all, so stale assets are exercised but never diffed. Rebuild+commit and add a CI check that dist matches a fresh build. | S | frontend |

## P2 — hardening & parity

| Fix | Why | Effort | Area |
|---|---|:--:|---|
| TerminalWorkspace defaultPane template drops workspace theme/font/connection | getPaneTemplate() builds a fresh TerminalBuilder seeded only with frameless()+squareCorners() plus the user closure, inheriting nothing from the workspace, so split panes render unthemed and local even when the workspace is SSH+themed. Inherit the workspace's connection/theme/font into the pane template. | M | components-api |
| TerminalDashboard inconsistencies: no auto frameless/square, silent maxOpen=4 hard cap | Unlike Grid and Workspace, Dashboard forwards source props verbatim (never normalizes chrome/squareCorners), so toggled terminals render with full chrome; and maxOpen silently clamps to 4 with no docblock/config knob (workspace.max_panes is configurable at 9). Normalize the pane look and make the cap documented/configurable. | M | components-api |
| EvaluatesOptions falsely claims Filament evaluate() parity — parameterized closures fatal | EvaluatesOptions::evaluate() is just `$value instanceof Closure ? $value() : $value` (zero-arg), but the docblock/CLAUDE.md assert parity with Filament's named-parameter DI. Any shared-trait closure declaring a parameter (e.g. ->height(fn($state)=>...)) fatals in TerminalBuilder. Either implement DI or correct the contract claim. | M | components-api |
| layout validate() misses duplicate split-node ids; fromArray(prefix:null) leaves terminal untypeable | validate() dedupes pane ids but not split ids, so a tree with two same-id splits passes and updateRatios drives both dividers from one id; fromArray(prefix:null) keeps tmux's single-char bindings so plain typing triggers actions. Low blast radius today (tree is #[Locked]) but real defensive-API gaps. Dedupe split ids and clear bindings when prefix is null. | S | layout-engine |
| TerminalWebSocketController ignores stream.websocket_url and hardcodes ratchet_host/port | The REST path builds the URL from ratchet_host/port (default 127.0.0.1) and never reads websocket_url, diverging from the Livewire path, so proxied/TLS custom frontends get an unreachable URL. Read websocket_url first like getWebSocketUrl. | S | cross-process |
| serve never validates the cache store is shared/persistent | The whole HTTP→serve handoff rides on Cache::put/pull against the default store; if it resolves to array or a per-process driver, every connection closes with configData===null and zero diagnostics. Add a serve preflight that warns when the default store is non-shared. | S | cross-process |
| No created_at index — retention cleanup and default Logs sort do full scans | cleanup/olderThan and the table defaultSort filter on created_at, but the only index is composite [user_id, created_at] (unusable for created_at-only range/sort). On a large logs table both the cleanup command and the resource list degrade. Add a standalone created_at index to the migration. | S | logging-filament |
| JS Filament asset registered under un-namespaced id 'stream-terminal' | CSS is registered as 'web-terminal-stream' but the JS bundle as bare 'stream-terminal' (ServiceProvider.php:78,82). FilamentAsset keys scripts globally by id, so co-installing the parent mwguerra/web-terminal can collide — violating the repo's own side-by-side isolation rule. Namespace the JS asset id. | S | config-packaging |
| Dead logging config keys + a README-documented env var that does nothing | logging.log_errors, max_output_length, truncate_output and README's WEB_TERMINAL_STREAM_MAX_OUTPUT_LOG are only read by the never-called command/output/error loggers, so they're inert in Stream mode yet still shipped and documented. Remove or clearly mark them dead to avoid operator confusion. | S | config-packaging |
| max_session_lifetime cleanup kills the PID but leaves the WS/bridge open | The 60s timer posix_kill(-9)s stale PIDs from the JSON registry but never closes the corresponding open WebSocket or removes the bridge from the server's live arrays, so a legitimately long interactive session gets its shell killed under it with a still-open (now dead) socket. Route lifetime enforcement through the server's session teardown, not just the registry. | M | ws-server |
| $wire.connect()/disconnect() emit events + log rows with no gate check | StreamTerminal::connect() dispatches TerminalConnectedEvent and logs with no useStreamTerminal check (unlike getWebSocketUrl), so any user with the page loaded can call the public Livewire methods to fabricate connect/disconnect audit rows. Gate the lifecycle methods consistently. | S | security |
| Filament Log resource UI, InteractiveSsh, and TerminalLogListener have zero coverage | TerminalLogsTable/Infolist/StatsOverview/list+view pages, the phpseclib3 InteractiveSsh wrapper (only exercised under Docker), and the opt-in listener are untested, so regressions in the audit UI and SSH option/error handling go uncaught on typical dev machines. Add Livewire/Filament resource tests and a non-Docker InteractiveSsh unit. | M | tests |
